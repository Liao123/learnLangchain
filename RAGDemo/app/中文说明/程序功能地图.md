# app 文件功能地图

这个文件夹里的 `.py` 是“当前能运行的 RAG 应用”，不是每个文件都要单独运行。

先只记住下面 3 个命令：

```powershell
# 1. 和咖啡店知识库聊天
py .\RAGDemo\app\rag_cli.py

# 2. 修改知识库 Markdown 后，重新制作检索索引
py .\RAGDemo\app\build_parent_child_index.py

# 3. 重建索引后，用固定题检查有没有找错资料
py .\RAGDemo\app\evaluate_retrieval.py
```

## 文件和作用

| 英文文件 | 中文作用 | 你什么时候需要它？ | 要直接运行吗？ |
| --- | --- | --- | --- |
| `rag_cli.py` | 咖啡店问答主程序 | 平时要问知识库问题时 | 要 |
| `build_parent_child_index.py` | 重建知识库索引的命令 | 修改 `data/source/长文档示例.md` 后 | 要 |
| `evaluate_retrieval.py` | 检索测试题 | 每次重建索引后 | 建议要 |
| `rag_core.py` | RAG 公共工具箱 | 被其他程序调用：读索引、BGE 检索、重排、hash | 不要 |
| `retrieval_cache.py` | 检索缓存工具箱 | 被 `rag_cli.py` 调用，保存相同问题的检索结果 | 不要 |
| `index_builder.py` | 索引构建工具箱 | 被 `build_parent_child_index.py` 调用 | 不要 |
| `metadata_filter_demo.py` | 元数据过滤单项示例 | 回顾“先按商品类型筛资料”时 | 可选 |
| `rerank_demo.py` | 重排序单项示例 | 回顾“BGE 初排后 reranker 重排”时 | 可选 |

`README.md` 只是 app 文件夹的使用说明，不是程序。

## 程序怎么互相调用？

```text
你要聊天
-> rag_cli.py
   -> rag_core.py：读取索引、BGE 检索、找回父章节、计算索引版本
   -> retrieval_cache.py：相同问题直接取缓存
   -> DeepSeek：根据找回的父章节生成回答

你修改了知识库资料
-> build_parent_child_index.py
   -> index_builder.py：Markdown 拆父章节、切子片段、生成索引内容
   -> rag_core.py：加载本地 BGE、计算新索引版本
   -> data/indexes/父子知识库索引.json：写入新的索引资料包

你想检查资料有没有找错
-> evaluate_retrieval.py
   -> rag_core.py：用与问答程序相同的 BGE 检索逻辑
   -> 打印每道固定测试题是否找回期待章节
```

## 建议阅读顺序

现在不需要一次看完所有 Python 文件。按下面顺序即可：

```text
第 1 步：rag_cli.py
        先只看 main()，理解“用户提问 -> 检索 -> AI 回答”。

第 2 步：build_parent_child_index.py
        理解“修改 Markdown 后，怎样得到新索引”。

第 3 步：index_builder.py
        它是上一步真正的拆分和向量生成逻辑；第 53 课 demo.py 已经先展开讲过。

第 4 步：rag_core.py
        这是前面检索、过滤、重排等课程积累下来的公共工具箱。
        不必一次读完；以后每复用一个函数，再回来看对应部分。

第 5 步：retrieval_cache.py
        回顾缓存课程时再看。
```

## 一句话区分

```text
主程序：给用户用的命令。
工具箱：主程序调用的代码，不直接运行。
单项示例：只演示一个能力，想复习时才运行。
```
