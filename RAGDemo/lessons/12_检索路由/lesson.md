# 模块 12：检索路由

## 这节课在学什么？

当资料不再只有一份知识库，而是分成多个主题时，先判断用户问题应该查哪个主题，再开始 BGE 检索。

本课把现有咖啡店资料逻辑上分成两份知识库：

- `会员与订单`：退款、咖啡豆、饮品、会员、积分、优惠、订单。
- `到店服务`：营业时间、周末、打烊、预订、到店。

用户问 `周末几点营业？` 时，程序先路由到“到店服务”，只让 BGE 在这份资料的 2 个子片段中检索，不再比较全部 9 个子片段。

## 它解决什么问题？

知识库越来越多时，全部资料混在一起检索会有三个问题：速度变慢、相似但无关的资料更容易进入候选、以及不同业务的权限边界不清晰。

例如公司可能同时有客服制度库、员工手册库、技术文档库。用户问报销流程时，不应该先去技术文档库里找最像的句子。

## 什么场景会遇到？

多产品线、多部门、多个国家地区、客户资料和内部资料分开保存时，都需要检索路由。它可以先按业务主题、用户身份、地区或产品类型决定检索范围。

## 这节要记住

- **路由**在检索之前：先决定“查哪一份资料”。
- **检索**在路由之后：再从允许范围里比较相似度。
- 本课路由规则是 Python 关键词规则，优点是简单、可解释；缺点是用户换一种说法可能没命中。
- 真正生产系统可以把规则、分类模型、LLM 判断和用户权限组合起来，但仍要保留“没有明确路由时怎么办”的规则。
- 本课规定：没有命中任何路由关键词时，不检索，提示应该拒答或转人工，而不是把全部资料硬查一遍。

本课第一次学习路由，所以关键词匹配、筛选子片段都直接写在 `demo.py`。先看懂变量如何变化；以后有多处需要路由时，才封装到 `app/`。

## 程序运行时发生了什么？

默认问题是：`周末几点营业？`

```text
用户问题：周末几点营业？
-> 路由规则发现“周末”“营业”
-> 命中“到店服务”知识库
-> 允许的父章节只有 parent_4：营业时间与到店服务
-> 允许的子片段只有 child_8、child_9（原来全库有 9 个）
-> BGE 只比较问题与 child_8、child_9 的向量
-> 找回 parent_4 完整章节
-> 后续 AI 只会收到这章资料
```

## 成功和故意失败测试

成功测试：直接运行默认问题。终端应显示路由命中 `到店服务`、允许子片段 `child_8` 和 `child_9`，最终完整章节是“营业时间与到店服务”。

第二个成功测试：把问题改成 `普通会员消费有什么积分？`。应命中 `会员与订单`，允许范围变成 `parent_1`、`parent_2`、`parent_3` 的子片段。

故意失败测试：把问题改成 `店里能维修电脑吗？`。没有路由关键词，程序会在调用 BGE 前停止。这是有意拒答，不是路由失败。

边界测试：把问题改成 `门店会员有什么优惠？`。`门店` 命中“到店服务”、`会员`和`优惠`命中“会员与订单”，程序会同时保留两个路由范围。它说明关键词路由可能模糊，生产中需要更细的规则或分类模型。
