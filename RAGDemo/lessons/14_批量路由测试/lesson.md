# 模块 14：批量路由测试

## 这节课在学什么？

第 41 课一次只测一题。这一课把多道题放进一个列表，再用一个 `for` 循环重复执行同一套“预期路由和实际路由比较”。

一句话逻辑：

```text
4 道测试题放进 test_cases
-> for 一次拿一题
-> 得到实际路由和实际动作
-> 与这题的预期值比较
-> 记录通过数量
```

本课只测试**路由和回退动作**，不加载 BGE、不做最终章节检索。这样你能只看“批量测试”这一个新概念。

## 它解决什么问题？

你改了路由关键词后，不能只手动试一题。批量测试可以一次检查：营业时间、会员积分、知识库外问题、多路由问题是否仍按规定处理。

## 这节要记住

- `test_cases` 是一个列表，列表的每一项是一道测试题。
- 每道题都有自己的 `question`、`expected_routes`、`expected_action`。
- `for test_case in test_cases` 的意思是“一题一题重复跑同一套检查”。
- `total_passed` 是通过题数，最后用 `total_passed / total_count` 看总体结果。
- 这一课不测 BGE，所以运行很快；下一步才会把路由测试与最终检索结果一起评估。

## 程序运行时发生了什么？

默认 `test_cases` 里有 4 项：

```text
第 1 项：周末几点营业？
-> 预期：['到店服务']，single_route

第 2 项：普通会员消费有什么积分？
-> 预期：['会员与订单']，single_route

第 3 项：店里能维修电脑吗？
-> 预期：[]，reject

第 4 项：门店会员有什么优惠？
-> 预期：['会员与订单', '到店服务']，multi_route_fallback
```

程序每次拿一项，调用第 40 课已经学过的路由代码，最后会打印：

```text
预期路由 -> 实际路由
预期动作 -> 实际动作
本题通过 / 失败
```

## 成功和故意失败测试

成功测试：直接运行，最后应显示 `测试总结：4/4 题通过`。

故意失败测试：把第 1 题的 `expected_routes` 改成 `["会员与订单"]`。实际路由仍会是 `["到店服务"]`，所以第 1 题会明确显示失败；其他题仍可通过。

另一个故意失败测试：在路由关键词里删掉 `"周末"` 和 `"营业"`，第 1 题会变成无路由。测试能告诉你：修改关键词破坏了原来的行为。

