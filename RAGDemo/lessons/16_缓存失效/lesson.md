# 模块 16：缓存失效

## 这节课在学什么？

第 43 课用“问题字符串”当缓存 key。现在只多加一个东西：**知识库版本号**。

一句话逻辑：

```text
缓存 key = 知识库版本 + 问题
-> 知识库版本变了
-> key 也变了
-> 旧缓存自然不会命中
```

## 它解决什么问题？

假设原来营业时间是晚上九点，后来资料改成晚上十点。

如果缓存还只用问题做 key：

```python
"周末几点营业？"
```

程序会继续拿旧答案，导致用户看到过期资料。

加上知识库版本后：

```python
"v1:周末几点营业？"
"v2:周末几点营业？"
```

它们是两个不同 key。资料升级到 `v2` 时，程序不会误用 `v1` 的缓存。

## 程序运行时发生了什么？

```text
知识库版本 v1
问题：周末几点营业？
-> key：v1:周末几点营业？
-> 存入 v1 的 result

知识库资料更新
-> 版本改为 v2
-> 同一个问题的新 key：v2:周末几点营业？
-> 字典里没有这个新 key
-> 旧 v1 缓存不会被使用
-> 应重新检索，并把新 result 存到 v2 key
```

## 这节要记住

- 缓存失效不是一定要把旧数据删除；也可以让新请求不再使用旧 key。
- 本课的 `v1`、`v2` 只是手动写的版本号。
- 生产中，重新建索引、资料更新、权限变化、阈值变化时，都应该影响缓存 key。
- 本课仍是内存字典；程序重启后字典本来就会清空。
