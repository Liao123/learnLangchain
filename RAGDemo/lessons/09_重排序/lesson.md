# 模块 09：重排序

## 这节课在学什么

先用 BGE 快速找一小批候选资料，再用 reranker 把候选资料重新排顺序，让最直接回答问题的资料排到前面。

## 它解决什么问题

BGE 擅长快速从很多资料里找“看起来相关”的内容，但前几名有时很接近。比如问“咖啡豆拆封后还能退款吗”，几段退款资料都会被找出来；真正最关键的是包含“拆封后不能退款”的那一段。

## 什么场景会遇到

知识库很大、BGE 的 top_k 里有多个相近候选、回答必须抓住细条件时都适合加重排序。常见做法是先让 BGE 找几十段，再只让 reranker 精读这几十段，避免让它阅读全部资料。

## 这节要记住

- **BGE**：快，负责从大量资料里初步找候选。
- **reranker**：慢一些，负责精读“问题 + 候选片段”这一对文字，再重新排序。

reranker 的分数和 BGE 分数来自不同模型，不能把 `0.8` 和 `0.8` 当成同一个意思。只看每个模型自己的排序即可。

## 程序运行时发生了什么

```text
用户问：咖啡豆拆封后还能退款吗？
-> BGE 先从全部子片段中找 3 个候选
-> 候选可能都和退款有关，但不一定最贴“拆封后”
-> 程序把“问题 + 候选 1”交给 reranker
-> 再把“问题 + 候选 2”交给 reranker
-> 再把“问题 + 候选 3”交给 reranker
-> reranker 给 3 个候选新分数
-> 程序按新分数重新排序
-> 最前面的片段更适合拿去组成最终资料
```

## 成功和故意失败测试

成功测试：运行默认问题，比较 `BGE 初始排序` 和 `reranker 重排序后`。顺序可能改变，也可能刚好不变；重点是看 reranker 确实对每个候选重新打分。

故意失败测试：把问题改成 `店里能维修电脑吗？`。重排序不能把无关资料变成正确答案，它只能在 BGE 已经找出的候选中重新排列。无关问题仍应依靠第 31 课的阈值拒答。

## 怎么运行和验证

从项目根目录运行：

```powershell
py .\RAGDemo\lessons\09_重排序\demo.py
```

本课不调用 DeepSeek，也不需要 API Key。首次运行可能需要下载 `BAAI/bge-reranker-base`；下载成功后可放到 `RAGDemo/models/bge-reranker-base/`，以后优先加载本地模型。
