# 模块 06：根据历史改写检索问题

## 这节课在学什么

用户说“那它呢”“这个能一起用吗”时，先让 AI 根据前面的聊天，把这句短话补成完整问题，再用完整问题去知识库查资料。

## 它解决什么问题

上一课虽然保存了聊天历史，但检索还是只看用户当前这一句话。`那它能和限时促销一起用吗？` 里的“它”没有名字，BGE 不知道要找金卡优惠、退款还是营业时间，所以容易找错资料。

## 什么场景会遇到

客服连续追问、用户省略主语、代词指代前文、聊天越来越自然时都会遇到。真实用户很少每句话都重新说全称。

## 这节要记住

程序会保留两句话：

- `question`：用户原话，用于最后回答，保证 AI 仍按用户自然说法交流。
- `retrieval_question`：补完整后的问题，只用于去知识库查资料。

## 程序运行时发生了什么

上一轮已经完成：

```text
用户：金卡会员有什么福利？
AI：金卡会员有两倍积分和现制饮品九折优惠。
```

这一轮用户问：`那它能和限时促销一起用吗？`

```text
用户原话
-> 第一次调用 AI，只让它根据历史补全问题
-> 得到：金卡会员的现制饮品九折优惠能和限时促销一起使用吗？
-> 程序拿这句完整问题去知识库查
-> 找到“会员积分与优惠”完整章节
-> 第二次调用 AI，发去“本轮完整章节 + 上一轮问答 + 用户原话”
-> AI 用用户原话回答
-> 程序保存这轮问答
```

重点：改写后的句子只负责查资料，不替代用户原话。这样检索听得懂“它”是谁，最终回答又不会显得生硬。

## 怎么运行和验证

从项目根目录运行：

```powershell
py .\RAGDemo\lessons\06_根据历史改写检索问题\demo.py
```

观察两行输出：`用户原话` 和 `程序拿去知识库查的问题`。后者应当出现“金卡会员”或“现制饮品九折优惠”。它的实际措辞可能略有不同，但意思必须完整。
