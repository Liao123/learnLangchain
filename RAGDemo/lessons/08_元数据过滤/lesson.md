# 模块 08：元数据过滤

## 这节课在学什么

在做相似度检索前，先用业务系统已经知道的条件缩小资料范围。比如订单系统知道用户买的是“现制饮品”，程序就只在现制饮品资料里查，不让咖啡豆规则参加比较。

## 它解决什么问题

用户只问“可以退款吗？”时，问题本身没有说买的是咖啡豆还是现制饮品。这两类商品的退款规则不同；如果让全部资料一起比，程序可能找错商品的规则。

## 什么场景会遇到

多门店、多产品、多语言、多年份制度、不同会员等级或不同用户权限的知识库。只要系统已经知道一部分背景，就应该先用这些背景筛资料。

## 这节要记住

元数据就是“资料的标签”。本课给每个父章节加了：

- `商品类型`：咖啡豆、现制饮品、会员服务或到店服务。
- `业务主题`：退款、订单修改、积分或营业时间。

元数据过滤不是让 AI 猜标签，而是使用订单、登录状态或页面选择器等业务系统已经知道的信息。

## 程序运行时发生了什么

```text
订单系统已知：用户买的是现制饮品
用户问：可以退款吗？
-> 程序先筛掉咖啡豆、会员和到店服务资料
-> 只留下“现制饮品”相关的子片段
-> BGE 只比较这些剩余片段
-> 找回“现制饮品与订单修改”完整章节
-> 后续如果调用 AI，只会把这章资料交给它
```

重点：过滤发生在相似度比较之前，不是先检索一堆资料后再随便删掉。

## 成功和故意失败测试

成功测试：默认条件是 `商品类型 = 现制饮品`，问题是 `可以退款吗？`，应该找回“现制饮品与订单修改”。

故意失败测试：把 `metadata_filters` 改成 `{"商品类型": "不存在的类型"}`。程序应该直接显示“没有任何资料符合这个元数据条件”，而不是从其他商品资料里乱找答案。
