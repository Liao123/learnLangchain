# 模块 07：RAG 测试题与效果评估

## 这节课在学什么

不要只问一两个问题就觉得 RAG 可用了。把常见问题和故意无关的问题写成固定测试题，每次改阈值、切块或模型后都重新跑一遍。

## 它解决什么问题

手动随便问，今天觉得“回答不错”，明天改了代码却不知道效果有没有变差。固定测试题能明确告诉你：退款题有没有找回退款章节、会员题有没有找回会员章节、知识库外的问题有没有被拒答。

## 什么场景会遇到

改了相似度阈值、换了嵌入模型、增加新资料、调整切块大小后，都应该跑一遍测试。真实项目上线前和更新知识库后更需要这样做。

## 这节要记住

本课先评两件事：

- **找对没有**：期待的父章节有没有被找回。
- **该拒答时有没有拒答**：知识库外的问题有没有被挡住。

本课暂时不评价 DeepSeek 的语言是否自然，也不评价回答有没有遗漏条件；那需要下一层“回答质量测试”。

## 程序运行时发生了什么

```text
程序准备 4 道固定题
-> 第 1 题拿去检索
-> 对比“期待章节”和“实际找回章节”
-> 打印通过或失败
-> 继续检查下一题
-> 最后统计一共通过几题
```

其中前三题是成功测试：退款、会员和营业时间都应该找对章节。最后一题是故意失败测试：`店里能维修电脑吗？` 应该不找回任何章节，直接拒答才算通过。

## 怎么运行和验证

从项目根目录运行：

```powershell
py .\RAGDemo\lessons\07_RAG测试题与效果评估\demo.py
```

这节不调用 DeepSeek，也不需要 API Key。观察最后的 `测试总结`：如果有失败题，不要急着改代码，先看失败题的最高相似度、期待章节和实际章节，判断是阈值问题还是检索找错资料。
