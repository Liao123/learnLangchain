# 模块 11：上下文压缩

## 这节课在学什么？

前面父子检索会找回完整父章节，这是为了避免只给 AI 半句话。但一章资料很长时，完整章节里会有很多和当前问题无关的句子。

这一课学习：**完整章节已经找回来后，再从这一章中挑出最能回答当前问题的几句，作为实际交给 AI 的资料。**

本课用 BGE 做“句子级第二次检索”。它不调用 DeepSeek，只把压缩前后和准备提交给 AI 的消息完整打印出来。

## 它解决什么问题？

例如用户问：`咖啡豆已经拆封了，还可以退款吗？`

完整的“退款办理规则”章节里，除了“拆封后不能退款”，还有订单凭证、七天期限、受潮、质量问题等内容。全部交给 AI 虽然更完整，但也更长、更容易分散重点。

上下文压缩后，只保留和“拆封 + 退款”最有关的句子，让 AI 更容易抓住本轮真正要回答的内容。

## 什么场景会遇到？

制度说明、产品手册、合同条款、FAQ 章节很长，而用户只问其中一个小条件时，都可能需要上下文压缩。它尤其适合“检索结果是完整章节，但完整章节又很长”的父子 RAG。

## 这节要记住

- 第一次检索：从整个知识库找回**完整父章节**。
- 第二次检索：只在找回的这章里，从多句话中挑出**最相关的几句**。
- 压缩后仍必须保留原章节标题和来源，方便追查。
- 压缩不是删得越多越好。若删掉例外条件，AI 可能答错。
- 知识库外的问题仍要靠第 31 课的阈值拒答；压缩不会让无关资料变正确。

本课第一次学习“章节内句子筛选”，所以所有新逻辑都直接写在 `demo.py`。先看清每一步；以后需要复用时，再决定是否封装到 `app/`。

## 程序运行时发生了什么？

```text
用户问：咖啡豆已经拆封了，还可以退款吗？
-> 第一次 BGE 检索：从全部知识库找回“退款办理规则”完整章节
-> 程序把这一整章拆成多句话
-> 第二次 BGE 检索：问题分别和每一句话比较
-> 选出分数最高的 2 句
-> 按它们原来在章节里的顺序重新排好
-> 组成 <压缩资料>
-> SystemMessage 放入压缩资料，HumanMessage 保留用户原问题
-> 本课打印这两条准备提交的消息，但不真的调用 AI
```

这不是“把原章节永久修改短”。原章节还在知识库中；`compressed_context` 只是本轮问答临时使用的短资料。

## 成功和故意失败测试

成功测试：直接运行默认题。你会看到完整章节、句子级相似度、保留的两句、以及最终的 `SystemMessage` 和 `HumanMessage`。保留内容应包含“咖啡豆已经拆封……门店不能办理退款”。

故意失败测试：把 `sentence_top_k` 改成 `1`，再把问题改成 `咖啡豆拆封后有质量问题怎么办？`。只留一句时，可能丢掉“质量问题按实际情况处理”的例外条件。这说明压缩数量不能只求少，必须用测试题验证。

另一个故意失败测试：把问题改成 `店里能维修电脑吗？`。即使压缩代码仍挑出几句咖啡店资料，它们也无法回答维修电脑；仍要在压缩之前使用相似度阈值拒答。

## 怎么运行和验证？

从项目根目录运行：

```powershell
py .\RAGDemo\lessons\11_上下文压缩\demo.py
```

本课不调用 DeepSeek，不需要 API Key，也不需要安装新库。
