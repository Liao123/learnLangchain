# 模块 23：自动缓存版本

## 这节课在学什么？

第 50 课的完整应用里，缓存版本还是手写的 `v1`。这一课让程序根据“父子知识库索引 JSON 文件的内容”自动生成版本。

一句话逻辑：

```text
索引文件内容
-> SHA-256 hash
-> 取前 12 个字符作为缓存版本
-> 索引内容变化，版本自动变化
```

## 它解决什么问题？

重建知识库索引后，人工忘记把 `v1` 改成 `v2`，旧缓存可能继续被使用。

用 hash 后，不需要人工判断版本号：只要索引 JSON 文件内容有任何变化，hash 就不同，缓存 key 自然不同。

## 程序运行时发生了什么？

```text
读取：父子知识库索引.json 的全部字节
-> 计算 hash，例如 8ab3...（每台机器/每次索引内容可能不同）
-> 得到版本：index-8ab3...
-> 组成缓存 key：
   public_customer:index-8ab3...:周末几点营业？

假设索引文件被重新生成
-> 文件字节变化
-> hash 变化
-> 新版本不同
-> 新 key 不会命中旧 key
```

## 这节要记住

- `hashlib` 是 Python 自带库，不是模型。
- SHA-256 是把任意内容计算成固定长度指纹的算法。
- 本课取 hash 前 12 位，只是为了让缓存 key 不太长。
- 内容相同，hash 相同；内容有变化，hash 基本一定不同。
- 本课先在 demo 展开实现；下一步才把自动版本接进 `rag_cli.py`。

## 怎么运行和验证？

```powershell
py .\RAGDemo\lessons\23_自动缓存版本\demo.py
```

本课不调用 BGE、不调用 DeepSeek，也不需要新库。
