# 模块 15：检索结果缓存

## 这节课在学什么？

同一个问题重复出现时，第一次正常检索；第二次不再调用 BGE，而是直接复用第一次的检索结果。

一句话逻辑：

```text
用户问题
-> 先看缓存字典里有没有这个问题
-> 有：直接取以前的 result
-> 没有：调用 BGE 检索，把 result 存进缓存
```

## 它解决什么问题？

用户反复问同一个问题、页面反复刷新同一资料、或多个相同请求同时到来时，重复做向量检索会浪费时间和计算资源。缓存能减少这些重复工作。

## 这节要记住

- 本课缓存的是**检索结果 `result`**，不是 AI 最终回答。
- `retrieval_cache` 是 Python 字典：键是问题字符串，值是该问题第一次检索得到的 `result`。
- 程序关闭后，这个内存字典会清空；它不是数据库缓存。
- 本课只做“完全相同字符串”缓存：`周末几点营业？` 和 `周末几点营业` 是两个不同键。
- 生产中缓存键还应包含知识库版本、用户权限、元数据过滤条件、`top_k` 和阈值，避免拿到不该复用的旧结果。

本课第一次学习缓存，所以缓存字典、命中判断、存入数据都直接写在 `demo.py`。

## 程序运行时发生了什么？

默认有三轮问题：

```text
第 1 轮：周末几点营业？
-> 缓存是 {}
-> 没找到
-> 调 BGE 检索
-> 把 result 存为：
   {"周末几点营业？": result_1}

第 2 轮：普通会员消费有什么积分？
-> 缓存没有这个问题
-> 调 BGE 检索
-> 缓存变成两个键

第 3 轮：周末几点营业？
-> 缓存已经有这个键
-> 直接取 result_1
-> 不调用 BGE 检索
```

## 成功和故意失败测试

成功测试：直接运行。最后应显示：

```text
BGE 实际检索次数：2
缓存命中次数：1
```

故意失败测试：把第 3 轮问题改成 `周末几点营业`，删掉中文问号。它和第 1 轮不是同一个字符串，所以会缓存未命中，BGE 实际检索次数变为 3。

另一个边界测试：修改知识库资料后，必须清空缓存或换知识库版本；否则缓存仍可能返回旧的 `result`。
