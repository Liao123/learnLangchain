# 模块 10：混合检索

## 这节课在学什么？

同一个问题，用两种方法分别找资料，再把两份结果合在一起：

- **BGE 语义检索**：看“意思像不像”。例如用户问“优惠能不能叠加”，即使资料写的是“不能同时使用”，BGE 也有机会理解两者相近。
- **BM25 关键词检索**：看资料里有没有出现用户说出的词。比如“九折”“限时促销”“订单号”这种必须精确命中的词。

本课使用 **RRF** 合并两份排序。它不比较 BGE 分数和 BM25 分数的大小，只比较每条资料在各自结果里排第几名。

这次是第一次学习 BM25 和 RRF，所以代码会直接写在 `demo.py` 中，不先藏进 `app/` 的函数。先把每一步看懂；以后同样逻辑要在多个程序复用时，再一起学习怎样封装。

## 它解决什么问题？

只用 BGE 时，模型可能理解了大概意思，却把某个很重要的精确词看得不够重；只用关键词时，用户换一种说法，资料里没有完全一样的字，就可能找不到。

混合检索不是让系统“更会回答”，而是让第一步“找资料”更稳一些。

## 什么场景会遇到？

商品型号、订单号、政策名称、优惠名称、报错码、专业名词等，通常需要关键词检索保底；用户的口语化提问、同义说法，则需要 BGE 语义检索帮忙理解。真实知识库经常同时有这两类情况。

## 这节要记住

- BM25 是关键词检索，不需要把文字转成 BGE 向量。
- 中文文本先用 `jieba.lcut()` 分成词。例如 `金卡会员的九折优惠` 会大致分成 `金卡`、`会员`、`九折`、`优惠` 等词。
- BGE 分数和 BM25 分数来自不同算法，不能直接相加。
- RRF 只看排名：第 1 名贡献比第 2 名大；一段资料同时出现在 BGE 和 BM25 前列，会得到两份贡献，所以会更靠前。
- 混合检索依然会为无关问题找出“最像的资料”。第 31 课的相似度阈值和拒答逻辑仍然需要保留。

## 程序运行时发生了什么？

这次用实际问题：`金卡会员的九折优惠能和限时促销一起使用吗？`

```text
用户问题
-> BGE 把问题变成向量，找出意思最接近的 3 个子片段
-> BM25 把问题分词，例如 ["金卡", "会员", "九折", "优惠", "限时", "促销", ...]
-> BM25 根据这些词，找出关键词命中最好的 3 个子片段
-> 程序分别打印两份列表
-> RRF 看每条资料在 BGE 和 BM25 中各排第几名
-> 两边都排得靠前的资料，排到混合结果的前面
-> 后续 RAG 再把这些子片段对应的完整父章节交给 AI
```

例如 `child_6` 同时写了“金卡会员”“九折优惠”“限时促销”。如果它在 BGE 是第 1 名、在 BM25 也是第 1 名，RRF 会给它两次加分；它通常会排在混合结果最前面。

## 成功和故意失败测试

成功测试：直接运行默认问题。你应该能在 BGE、BM25、混合结果三栏里看到 `child_6`，并且在资料文字中看到“金卡会员”“九折优惠”“限时促销”。三栏的具体顺序可能不同，这是正常的；重点是理解三栏各自负责什么。

故意失败测试：把问题改为 `店里能维修电脑吗？`。混合检索仍会列出几段“相对最像”的咖啡店资料，但它们没有回答“维修电脑”。这说明混合检索不能代替第 31 课的阈值拒答。

## 怎么运行和验证？

本课第一次需要两个新库。先在项目根目录运行：

```powershell
py -m pip install jieba rank-bm25
```

然后运行：

```powershell
py .\RAGDemo\lessons\10_混合检索\demo.py
```

本课不调用 DeepSeek，也不需要 API Key。它只把三种检索排序过程打印出来，让你清楚看到资料是怎样被找出来、合并的。
